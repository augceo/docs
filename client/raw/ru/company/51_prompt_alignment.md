# 51: Запрос/Согласование

> [!DEFINITION] Документ Согласования
> Автоматически сгенерированный синтез процесса ревью, который фиксирует общее согласие, разрешенные конфликты и точные инструкции для выполнения.

> Sidenote:
> - См. определение в: :term[22: Компания/Согласование]{href="./22_document_alignment.md", canonical="22: Company/Alignment"}.

## Правила Инвариантности

**СТРОГО ПРИДЕРЖИВАЙТЕСЬ ЭТИХ ПРАВИЛ:**

1.  **Временное хранилище:** Вы МОЖЕТЕ создавать `{OUTPUT_DIR}/{FILENAME}.ndjson` для хранения необработанных комментариев. НЕ создавайте другие временные файлы.
2.  **Получение за один проход:** Получайте все необходимые данные (комментарии) за один вызов API для каждого ресурса. НЕ используйте пагинацию вручную или циклы.
3.  **Источник для валидации:** Всегда проверяйте данные на основе **существующего контекста** (JSON), никогда не запрашивайте их повторно для проверки.
4.  **Язык:** Выходной документ ДОЛЖЕН быть на **целевом языке**, указанном во входных параметрах (за исключением кода/технических терминов и оригинальных цитат из комментариев).
5.  **Полнота:** Каждый комментарий должен быть учтен в Отчете о покрытии.
6.  **Без перезапусков:** Если обнаружены проблемы (например, отсутствующие элементы, пробелы в покрытии), НЕ перезапускайте процесс. Исправьте конкретную проблему (добавьте намерение, исправьте формулировку) и продолжайте.
7.  **Скрытый анализ (Без скриптов):** НЕ используйте скрипты (Python/Shell) для анализа, подсчета или синтеза. Вся обработка ДОЛЖНА выполняться «в контексте», используя скрытые возможности LLM.

## Цель

Документ Согласования — это мост между обсуждением (в Pull-запросах) и исполнением. Он фиксирует «Итоги ревью» и «Консенсус», которые формируются в ходе проверки.

### 2. Получение Данных

> [!WARNING] БЕЗ ВРЕМЕННЫХ ФАЙЛОВ
> **НЕ СОХРАНЯЙТЕ** загруженный контент во временные файлы (например, `process.md`, `pr.json`), если это не разрешено явно.
> **Причина:** Временные файлы засоряют рабочее пространство и запрещены Правилом Инвариантности №1.
> **Исключение:** ЕДИНСТВЕННЫЙ разрешенный временной файл — это `{OUTPUT_DIR}/{FILENAME}.ndjson` для необработанных комментариев.
>
> Все остальные команды (curl, gh api) должны выводить результат непосредственно в стандартный вывод инструмента.

**ОГРАНИЧЕНИЕ:** Вам разрешено выполнять ТОЛЬКО следующие внешние запросы:

1.  **HTTP GET** через curl на `https://idealic.academy/raw/en/company/02_process.md`
2.  **HTTP GET** через curl на `https://idealic.academy/raw/en/company/50_prompt_truth.md`
3.  **Вызов GitHub Pull Request API** (для определения автора)
4.  **Вызов GitHub Comments API** (с помощью однострочной команды ниже)

НЕ пытайтесь получить diff PR или список коммитов. Это выходит за рамки ваших полномочий.

**Шаг 1: Загрузка Обязательных Документов**
Загрузите указанные URL. **Обрабатывайте каждый документ отдельно.**
**Ограничение:** ВАЖНО: Вы должны использовать **отдельные вызовы инструментов** для каждого документа. НЕ объединяйте команды с помощью `&&` или `;`.

**Шаг 2: Получение Деталей PR (Определение Ролей)**
Получите детали PR, чтобы определить Автора.

```bash

```

**Шаг 3: Получение Комментариев**

1.  **Получение в файл:** Выполните именно эту команду, чтобы сохранить комментарии в `{OUTPUT_DIR}/{FILENAME}.ndjson`.

    ```bash
    gh api graphql -F owner='{OWNER}' -F repo='{REPO}' -F pr={PR_NUMBER} -f query='\n      query($owner:String!, $repo:String!, $pr:Int!) {\n        repository(owner:$owner, name:$repo) {\n          pullRequest(number:$pr) {\n            reviewThreads(first: 100) {\n              nodes {\n                isResolved\n                comments(first: 50) {\n                  nodes {\n                    databaseId\n                    body\n                    author { login }\n                    createdAt\n                    path\n                    diffHunk\n                    replyTo { databaseId }\n                    url\n                    reactions(first: 10) { nodes { content } }\n                  }\n                }\n              }\n            }\n          }\n        }\n      }\n    ' --jq '\n      .data.repository.pullRequest.reviewThreads.nodes[]\n      | .isResolved as $resolved\n      | .comments.nodes[]\n      | {\n          id: .databaseId,\n          body,\n          user: (.author.login // "ghost"),\n          created_at: .createdAt,\n          path,\n          diff_hunk: .diffHunk,\n          in_reply_to_id: .replyTo.databaseId,\n          html_url: .url,\n          reactions: ((.reactions.nodes | map({(.content): 1}) | add) // {}),\n          is_resolved: $resolved\n        }\n    ' | jq -s '\n        group_by(.in_reply_to_id // .id)\n        | map(sort_by(.created_at))\n        | sort_by(.[0].created_at)\n        | flatten\n        | to_entries\n        | map(.value + {index: ("§" + ((.key + 1) | tostring)), anchor: (.value.html_url | split("#") | last)} | del(.html_url))\n        | group_by(.in_reply_to_id // .id)\n        | sort_by(.[0].index | ltrimstr("§") | tonumber)\n        | map(map({\n        index,\n        id,\n        anchor: .anchor,\n        path,\n        body,\n        user,\n        created_at,\n        diff_hunk: (.diff_hunk | if length > 350 then .[:350] + "..." else . end),\n        in_reply_to_id,\n        reactions: (.reactions | with_entries(select(.value > 0))),\n        is_resolved\n        }))\n        | map(.[0] as $root | [$root] + (.[1:] | map(del(.diff_hunk, .is_resolved, .path))))\n        | map(map(del(.in_reply_to_id)))\n        | .[]\n    ' -c > {OUTPUT_DIR}/{FILENAME}.ndjson
    ```

### 4. Методология: Интеллектуальный Синтез

**Метод: Интеллектуальный Синтез**

- :term[02: Компания/Процесс]{href="https://idealic.academy/en/company/02_process.md/", canonical="02: Company/Process"}
- :term[50: Запрос/Истина]{href="https://idealic.academy/en/company/50_prompt_truth.md/", canonical="50: Prompt/Truth"}

**Ограничение:** Выходной документ должен быть на **Целевом языке** ({language}).

- **Переводить:** Все заголовки, описания, анализ, названия намерений, обоснования и структурный текст.
- **Оставлять без изменений:** Технические термины, пути к файлам, фрагменты кода, прямые цитаты и слово **«Alignment»** (в заголовках).
- **Глоссарий (для русского языка):**
  - Proposal: Предложение
  - Intent: Намерение
  - Agreed: Согласовано
  - Done: Готово
  - Rejected: Отклонено
  - Discussion: Обсуждение
  - Clarification: Уточнение
  - Deferred: Отложено
  - Outdated: Устарело

**Приоритет — полнота:**

- **Фиксируйте детали:** Сохраняйте технические инструкции.
- **Атомарность:** Одно Намерение = Одно отдельное техническое изменение.
- **Покрытие:** Соотнесите каждый комментарий.

    - Статус: Черновик консенсуса

    {{WARNING_PLACEHOLDER}}

#### 5.2. Фаза 2: Загрузка Контекста

2.  **Чтение в контекст:**
    - Прочтите `{OUTPUT_DIR}/{FILENAME}.ndjson` (порциями по 25 строк).

#### 5.3. Фаза 3: Обзор

**Анализ:**

1.  **Цель рецензента:**
2.  **С чем автор согласен:**
3.  **С чем автор не согласен:**
4.  **Общий контекст:**
5.  **Недопонимания:**

7.  **Новые открытия:**
8.  **Связанные документы:**

**Генерация:**

#### 5.4. Фаза 4: Намерения

**Анализ:**
Цель: **Гипергранулярная Атомарность**.

- **Правило разделения:** Никаких «И». Разделяйте сложные ветки обсуждений.
- **Атомарность:** Одно Намерение = Одно отдельное техническое изменение.
- **Приоритет деталей:** **НЕ СЖИМАЙТЕ.** Предоставляйте полный контекст и содержание. Избегайте кратких выводов; подробно объясняйте «Что» и «Почему».
- **Включение кода:** **ВСЕГДА** включайте соответствующие `diff_hunk`. Если их несколько:
  - **Перечислите все**, если они короткие/ключевые.
  - **Сжимайте** разумно, если они слишком длинные (например, `... code ...`), но оставляйте видимыми ключевые изменения в логике.
- **Определение контекста:** Определите целевую область для каждого намерения:
  - **Спецификация:** Изменения в логике/требованиях (markdown-файлы).
  - **Код:** Детали реализации (файлы ts/tsx).
  - **Тесты:** Тестовые случаи/наборы.
  - **Процесс:** Изменения в рабочем процессе/документации.
- **Логика решений автора:**
  - **Явное:** Используйте словесный ответ автора, если он содержит четкое решение.
  - **Подразумеваемое (Эмодзи):** Если словесного ответа нет, проверьте наличие эмодзи на комментарии _рецензента_ (например, 👍, 🚀, 👀). Предположите, что они от автора, и интерпретируйте их как согласие/подтверждение.
  - **Без домысливания:** Если нет ни того, ни другого, отметьте как «Ожидает/Нет ответа». НЕ придумывайте решение.
- **Определения статусов:**
  - **Готово:** Автор явно заявляет о завершении, И нет противоречивых последующих сообщений.
  - **Согласовано:** Достигнут консенсус, действие ожидается.
  - **Отклонено:** Автор отказался с обоснованием, дальнейших возражений нет.
  - **Обсуждение:** Активная дискуссия, четкого консенсуса пока нет.
  - **Уточнение:** Отсутствует контекст или требования неоднозначны.
  - **Отложено:** Действительное замечание, но перенесено на будущую работу/задачу.
  - **Устарело:** Намерение из предыдущего согласования, неактуальное в текущем объеме работ.
- **Интерпретация в контексте:**
  - **Markdown-файлы (`*.md`):** Комментарии часто относятся к логике **Спецификации** или **Предложения**. (например, «Удалить флаг» = «Обновить спецификацию, чтобы удалить флаг», а не обязательно «Немедленно удалить код»).
  - **Файлы с кодом:** Комментарии относятся к деталям реализации.
  - **Действие:** Явно укажите контекст (Спецификация или Код) в полях `Обоснование` или `Намерение`, если есть неоднозначность.

**Создание черновика (Обязательно):**

1.  **Генерация в контекст:** Выведите полный список «Свежих намерений», основанный _только_ на текущем анализе, в контекст чата.
2.  **Формат:** Используйте стандартный шаблон Намерения.
3.  **Метка:** Предварите его заголовком `### Черновик Свежих Намерений`.
4.  **НЕ** записывайте в файл на этом этапе.

#### 5.5. Фаза 5: Эволюция (Слияние)

**Цель:** Гармонизировать «Только что сгенерированные намерения» (Фаза 4) с «Предыдущим Согласованием».

1.  **Проверка конфигурации:**
    - Если `merge_alignments` равно **false**: пропустите шаги 2-3. Используйте «Черновик Свежих Намерений» напрямую. Переходите к перезаписи.

2.  **Получить предыдущее Согласование:**
