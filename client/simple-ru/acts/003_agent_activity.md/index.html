003: Агент/Действие

  • Требуется: 002: Агент/Инструмент
Действие

Чёткая функция, которая выполняет реальную работу для Инструмента. Это способ делать то, с чем ИИ не справится сам в своей «голове» (например: сделать запрос куда-то в интернет, сохранить данные в базу или запустить настоящую программу).

Протокол Действий (Activity) описывает, как Инструменты работают на самом деле с помощью настоящего кода. Если Инструмент — это как пункт в меню, который описывает блюдо, то Действие — это сам процесс готовки на кухне, то есть его реализация.

Два списка: Меню и Рецепты

Наша система использует две отдельные коллекции (списка), чтобы отделить то, что мы просим сделать, от того, как именно это выполняется:

  • Список Инструментов: Хранит описания и схемы всех Инструментов (наше меню).
  • Список Действий: Хранит конкретный исполняемый код — асинхронные функции (Действия), которые делают всю реальную работу (наша книга рецептов).

Такое разделение делает систему невероятно гибкой. Оно позволяет ИИ иногда самому придумывать ответы («в уме»), а иногда — использовать реальный код. При этом, код можно легко менять и тестировать в разных условиях, не меняя само описание Инструмента.

Как зарегистрировать Действие

Мы регистрируем Действие под уникальным именем, которое потом связывает его с нужным Инструментом. Код (функция) при этом получает три важные вещи для работы:

  • call (вызов): Конкретный Запрос. В нём лежат все параметры задачи, а также служебные настройки (имена которых начинаются с _), которые направляют процесс.
  • tool (инструмент): Схема самого Инструмента. Это помогает коду понять, чего вообще от него ждут (например, в каком формате нужно вернуть результат _output).
  • context (окружение): Небольшой набор прошлых сообщений. Это не вся история переписки, а только то, что нужно прямо сейчас. Этим управляет протокол Областей видимости, так что мы передаем только ту информацию, которая действительно нужна.

Если Действие возвращает готовое сообщение (Data Message), система просто добавит его в ход работы как есть. Если функция возвращает просто текст или числа, система сама красиво упакует это в правильное сообщение и направит по пути сохранения (_outputPath), который был указан в запросе.

Реализация Действия

// Регистрируем функцию ДЕЙСТВИЯ.
// Обычно мы даем Действию то же имя, что и Инструменту.
// Типы автоматически подхватываются от Инструмента.
Activity.register('weatherCheck', async (call, tool, context) => {
  const data = await weatherAPI.get(call.location);
  return { temperature: data.temp, conditions: data.desc };
});

Соответствующая схема Инструмента

Tool.register('weatherCheck', {
  type: 'object',
  description: 'Получает текущую погоду для выбранной локации.',
  properties: {
    _tool: { type: 'string', const: 'weatherCheck' },
    location: { type: 'string' },
    _output: {
      type: 'object',
      properties: {
        temperature: { type: 'number' },
        conditions: { type: 'string' },
      },
      required: ['temperature', 'conditions'],
    },
  },
  required: ['location'],
});

Два режима работы: В уме (Скрытое) и Наяву (Явное)

Система умеет выполнять вызов Запроса двумя совершенно разными способами:

    • 104: Концепция / Скрытое
    Скрытое исполнение (В уме): Использует силу нейросети. Агент сам «обдумывает» задачу и выдаёт результат сразу же. Это режим по умолчанию, когда для задачи не написано специального реального кода.
  • Явное исполнение (Наяву): Запрос передаётся настоящей функции с кодом, которая и выполняет работу. Это нужно для взаимодействия с внешним миром (скачать файл, сделать запрос на сайт) или там, где нужна 100% точность вычислений.

Скрытые шаги решаются мгновенно

Фраза «сразу же» значит больше, чем кажется. Именно поэтому скрытые шаги так полезны, даже не только на этапе прототипирования проекта.

Если у Запроса нет привязанного кода (в поле _activity пусто), то система вписывает ответ в тот же самый ход, когда агент вообще об этом попросил. Не нужно ничего ждать. Ответ сразу кладётся по нужному пути (Путь к результату), и другие задачи могут прочитать этот ответ прямо на том же ходу.

  • 011: Агент/Выражения — вычисляемый параметр обычно сразу же подхватывает результат скрытого выполнения прямо на том же ходу.

Скрытый Запрос без указанного результата (_output) не выполняется сразу: он просто «уезжает» в План на следующий ход. Это тратит целое действие зря. Поэтому всегда заполняйте _output прямо в момент создания запроса (когда данные у вас уже есть) и оставляйте его пустым, только если результатов ещё физически не существует.

Поэтому, если агенту нужно принять какое-то решение — например, «какие из этих текстов позитивные?» — ему не нужен код. Он делает вывод в уме, и этот вывод сразу превращается в значение, с которым могут работать другие инструменты. Это не просто «мысли вслух», которые кто-то должен прочитать; это быстрый и четкий ответ, полученный за один шаг, а не за три.

Как система понимает, что нужно делать (Стратегия разрешения)

Вам почти ничего не нужно настраивать. Система автоматически понимает, какой режим включить (в уме или наяву). Главную роль тут играет поле _activity в схеме Инструмента:

  1. Явное поле _activity: Если в описании Инструмента указано имя нужного Действия, система найдет эту функцию в реестре и запустит её.
  2. Одинаковые имена (Рекомендуется): Если поля _activity нет, система попытается найти код (Действие), который назван точно так же, как и Инструмент. Если находит — автоматически его использует.
  3. Переход в режим «в уме»: Если код не найден, поле _activity остается пустым, и это сигнал, что задачу придется решать скрыто, силами нейросети.

Благодаря этому разработка идет очень быстро:

  • Просто называйте код так же, как инструмент — и всё заработает само.
  • Если вы пока не написали код, инструменты будут безопасно работать в режиме «в уме».
  • Если вам нужно, чтобы разный код выполнял одно и то же действие, вы просто указываете его имя напрямую через поле _activity.

Связь с другими частями системы

Действие не работает в вакууме. Оно общается с другими правилами, чтобы получать данные и контекст безопасно:

    • 004: Агент/Запрос
    • 008: Агент/Вывод
    • 013: Агент/Экземплирование

    Запрос: Параметр call дает коду всю нужную информацию о задаче. Там есть не только сами данные, но и мета-свойства, например, _outputPath (куда положить результат) или _instance (ссылка на конкретный элемент при массовой обработке). Это позволяет коду участвовать в сложных цепочках.

    • 015: Агент/Области видимости

    Области видимости: Параметр context настраивается через протокол Областей видимости. Свойство _scopes работает как фильтр — оно решает, какие из сообщений среды (например Состояние или Ввод) можно показать внутри Действия. Благодаря этому код не отвлекается на лишний информационный шум из общей среды агента.

  • Развилки на пути: Код может возвращать не только простое число или строку, но и готовое сообщение. И это важно для обработки ошибок. Когда код видит, что результат нужно записать с условием успеха или провала (например, _outputPath: '†state.success <|> †state.error'), он сам понимает, удалась ли операция, и затем создает сообщение так, чтобы сразу отправить данные в нужную (успешную или ошибочную) ветку плана. Это дает коду полный контроль над маршрутом агента.

Почему важно разделять Меню и Рецепты

Если бы мы навсегда склеили описание того, что ИИ может делать (Инструмент), с тем, как он это делает (Действие), это превратило бы систему в хаос. Чтобы поменять логику ИИ на внешний API, пришлось бы переписывать код внутри всех агентов, которые знали этот навык.

Архитектура двух списков решает эту проблему заранее. Для агента «меню» навыков всегда выглядит одинаково, неважно, как оно реализовано на «кухне». Это даёт огромные плюсы:

  • Смена логики ничего не ломает агентам: Вы можете переключаться со скрытого мышления на реальный внешний API (и обратно) — сам агент этого даже не заметит, переделывать его не придется.
  • Тестирование (А/Б тесты): Вы можете легко проверять, чья логика лучше справится с задачей: рассуждения нейросети или профессиональная внешняя программа.
  • Постепенные запуски: Можно давать обновленный код только части агентов, оставляя других работать на старой версии или в скрытом режиме.

От замысла к реальным шагам

Разделив то, «что нужно» (Инструмент), и то, «как это сделать» (Действие), мы сделали систему невероятно гибкой. Но это лишь часть картины. Когда у нас есть интерфейс и реализация, их нужно правильно запускать, контролировать последовательность и управлять потоком запросов.
